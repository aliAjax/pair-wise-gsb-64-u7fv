# 食品工厂HACCP控制计划与偏差处置平台

独立React前端工程，采用Fluent UI、Redux Toolkit、RTK Query、React Router、Vite和TypeScript。数据通过浏览器持久化，无需后端。

## 功能

- 生产批次、放行状态、监测点与隔离范围；待核晚到记录和未关闭偏差均阻止放行。
- HACCP流程图和控制矩阵编辑，记录关键限值、频率和纠偏措施。
- **关键限值生效时间线**：每个控制点的限值按 `effectiveAt` 形成版本链。
  - 发布新版后旧版整体标记失效；**未锁定的旧读数先置为“待重判”，再按各自记录时点选版复判**（取 effectiveAt ≤ 记录时点 的最后一版）。
  - 已判偏差和已放行/报废批次的结论锁定，保留原依据版本，限值更新不改写。
- **批次详情按限值版本前后拆分监测段**，每条读数显示记录时点、补录时间、依据版本（现行/已失效）、判定状态和复判留痕。
- **偏差版本链**：初判版本冻结；复判按读数记录时点在当前时间线重新选版，**另存一版**，结论翻转自动退回调查，历版结论不改写。
- **晚到补录待核队列**：记录时点无可用版本，或现场声称依据与按时点选版结果不一致时进入待核；质量核选依据后才产生结论，不直接改写既有判定。
- **并发提交**：两个窗口同批次、同控制点、记录时点±60秒内的提交视为同一读数；后到一方挂起并在冲突面板重新选择依据后补提，先到结论不被覆盖。
- **写入失败恢复**：写入批次记录完成度并建立带哈希链的时间线检查点；失败不产生检查点，恢复时从最后完整检查点按客户端幂等号只补未完成记录，恢复后追加新检查点。
- 完整版本化审计（限值版本/监测判定/偏差处置/批次流转/写入恢复五类，带版本引用）、检查点哈希链校验和JSON追溯包导出。

端口为`18464`。

```bash
npm install
npm run build
npm run dev
```
